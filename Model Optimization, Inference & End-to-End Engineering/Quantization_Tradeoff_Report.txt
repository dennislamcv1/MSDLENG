Dynamic post-training quantization reduced the DistilBERT SST-2 classifier from 255.3 MB (FP32 ONNX) to 64.3 MB (INT8), a 74.8% size reduction, since the weights drop from 32-bit floats to 8-bit integers. On a 2-core x86 (AVX2) CPU, using one identical 13-token input with 10 warm-up and 50 timed passes (median of seven runs), p50 latency fell from 15.0 ms to 10.4 ms (30.9% faster) and p95 from 18.1 ms to 13.3 ms (26.6% faster), a slightly smaller gain in the tail. On the three sample sentences, the INT8 model is expected to return the same labels as FP32 (POSITIVE, NEGATIVE, NEGATIVE), with only small shifts in confidence.

Dynamic PTQ is worth adopting first: a 4x smaller model and roughly 1.4x faster median inference, with no retraining or calibration data. It does not yet prove the real-time requirement is met. The product team's latency budget should be compared against p95, not p50, since one request in twenty still takes longer than 13.3 ms, and three short sentences say nothing about accuracy. Before deployment, both models should be scored on the full SST-2 validation set (872 sentences) and benchmarked on realistic feedback lengths. If p95 still misses the budget, static PTQ should be investigated next: calibrating activation ranges on real feedback samples removes the per-request range computation and lets more operators run in INT8. QAT should be reserved for cases where PTQ costs more than about one accuracy point, because it requires retraining.
